# 家庭持续阅读接力

句象书店作家对谈（北京、长沙、武汉……）之后的家庭持续阅读服务合同基线：把读者与监护关系、年龄与兴趣、
书目版本、门店库存、跨店共享借阅、阅读指导、作家活动、家庭反馈与隐私授权连成一条可追踪的接力链。

## 内容

| 路径 | 说明 |
|---|---|
| `docs/domain-design.md` | 领域设计：角色与代行、授权模型、限界上下文、事件信封、关键不变量与开放问题 |
| `contracts/event.schema.json` | 事件信封 JSON Schema（基线 5 字段 + context/actor/payload/request_id 等） |
| `contracts/event-catalog.json` | 事件目录：每种 kind 的上下文、载荷必填字段、是否外部触发（幂等） |
| `src/contract.py` | 信封校验：按目录核对 kind、context、payload 字段与类型、request_id |
| `src/rules.py` | 纯函数业务规则：授权折叠、适龄、快照还原、幂等、借阅状态机、闭店影响面、报名/候补/权益分账、指导资格、接力追踪 |
| `fixtures/event.json` | 单事件样例 |
| `fixtures/relay.json` | 武汉场对谈后的一条完整接力链样例（含闭店改期、跨店在途、事后书目更新） |
| `tests/` | 信封与目录一致性、全部关键规则的可执行校验 |

## 关键原则（详见设计文档）

1. 事件只追加、不覆盖；当前状态全部由事件流折叠得到。
2. 家长可代办，但**孩子本人的撤回优先**，家长不能越过。
3. 儿童视图只暴露适龄内容；年龄按出生日期动态计算。
4. 推荐发出时快照书目说明与理由；说明更新后历史推荐仍可逐字还原。
5. 跨店借阅有在途/逾期状态；重复扫码与断网补传靠 `request_id` 幂等，不重复扣库存与次数。
6. 临时闭店只重排命中闭店区间的未完成取/还安排，不动活动与其他门店。
7. 活动报名、候补、会员权益三本账分开；借阅次数另计，互不串账。
8. `correlation_id` 让运营能从一次对谈追到后续借阅、指导与家庭反馈。
9. 家庭端与门店读同一事件流，地点/时间/可借状态一致；柜台记录不再是第二事实源。
10. 阅读指导资格只来自角色授权，规则函数拒绝任何消费金额类入参。
